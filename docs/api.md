# Web API

The live demo serves one same-origin FastAPI application. It deliberately does not expose autogenerated OpenAPI, Swagger or Redoc pages. All requests involving a session are JSON; responses include real model/physics values, not prerecorded states.

Base URL: **`https://actionworld-lite.vercel.app`**

## Public routes

| Route | Purpose |
| --- | --- |
| `GET /` | Browser UI |
| `GET /m8-style.css` | Static stylesheet |
| `GET /m8-app.js` | Static client script |
| `GET /api/health` | Lightweight app mode and configuration-readiness flag |
| `POST /api/session` | Reset real MuJoCo scene and create signed session |
| `POST /api/action` | Run a real action from the signed saved state |

### Start a session

```bash
curl --fail-with-body -X POST https://actionworld-lite.vercel.app/api/session \
  -H 'Content-Type: application/json' \
  -d '{}'
```

Response fields include `session_token`, `scored_actions` (0), `physics_time_s` (approximately 0.05), `real_rgb_png` (a PNG data URL), `actual`, and null `prediction` and `metrics` at initial reset. The startup zero-action physics step is intentionally **not scored**.

### Execute an action

```json
{
  "session_token": "<signed token returned by /api/session>",
  "step_size_mm": 10,
  "direction": "right"
}
```

Use `POST /api/action` with **exactly** these three JSON fields. Allowed step sizes are integer **5, 10, 20**; directions are lowercase `up`, `down`, `left`, `right`. The response includes a **new** `session_token`, `physics_time_s`, `scored_actions`, `real_rgb_png`, `actual`, `prediction`, `metrics`, `ic01_forward_calls: 1`, `physics_step_calls: 1`, and the submitted action's direction/size. Positions use **meters**, the displayed errors use **centimeters**, and corrections are presented in **millimeters**.

`actual` contains actual object XY/yaw, pusher XY and post-step contact. `prediction` and `metrics` are defined by the current [`m8_web/model_adapter.py`](../m8_web/model_adapter.py); this guide intentionally does not promise unverified subfield names. Do not parse the signed token as an API of physical labels or a trusted public data format.

## Rejections and failure behavior

| Condition | Recorded HTTP status |
| --- | --- |
| Signature altered, invalid or expired token | `401` |
| Invalid direction or unsupported step size | `422` |
| Missing/extra action fields or malformed body | `400` |
| Request body beyond 64 KiB | `413` |
| Attempt to take a 65th scored action | `409` |
| Real model or MuJoCo unavailable | `503` |

Failures do **not** yield a fabricated continuation token. The browser retains the previous accepted token and can Reset after an error.

## Token, security and privacy

The token contains the MuJoCo integration state and two genuine RGB observations, plus signature, expiry, build fingerprint and sequence metadata. HMAC provides **integrity**, not encryption, global exactly-once delivery or replay prevention. The token expires after 15 minutes; clients must serialize actions. The UI uses same-origin resources and does not require cookies or a user account.

Weights, fitted coefficients, signing secrets, training archives and server source files are not public API routes. See the [architecture](architecture.md) and [deployment record](M8_STEP3_DEPLOYMENT.md).
